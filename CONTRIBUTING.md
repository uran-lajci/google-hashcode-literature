# Contributing

Thank you for your interest in contributing to google-hashcode-literature!

Contributions are welcome, especially new academic works on Hash Code problems and corrections to existing entries.

## How to Contribute

1. Fork this repository on GitHub.
2. Clone your fork and create a branch for your changes.
3. Make your changes and check that all links work and the Markdown renders correctly.
4. Commit and push your changes to your fork.
5. Open a pull request against the original repository, explaining what you added or changed and why.

If you know of a relevant work but don't want to edit the files yourself, you can open an issue with the reference and a link instead.

## What You Can Contribute

- Add published works that study a Hash Code problem: journal and conference papers, theses, preprints, technical reports, and conference presentations.
- Add an existing work to another problem it also covers.
- Fix incorrect titles, authors, venues, years, or broken links.
- Improve the descriptions of existing entries.

Please note: Only include works that use or study a Google Hash Code problem or its official instances. Do not add competition solution repositories, blog posts, videos without an academic context, or works that merely mention Hash Code in passing.

## Guidelines

- Add each entry under the section of the problem it covers, using the format of the existing entries:

```markdown
  - **[Title of the Work](link)**, A. Author, B. Author, *Venue*, volume(issue), pages (year).
    One to three sentences describing what the work does with the problem and its main result.
```

- Link to the official version (DOI, publisher page, or institutional repository). If there is also a free version, such as an arXiv preprint, you may add it as a second link.
- If a work covers several problems, add it under each one, with a description specific to that problem.
- If the work is not in English, give an English translation of the title and note the language.
- Keep descriptions short, factual, and based on the work itself; avoid promotional language.
- Keep entries within a section in chronological order, oldest first.

All contributions are subject to review before being merged.

Thank you for helping improve the project!
